# Windows Event Log Analysis with Hayabusa

## 1. Project Overview

In this project, the **Hayabusa** tool was used to analyze Windows Event Logs.

The main objective was to investigate system events, evaluate security detections, and distinguish suspicious activities from normal system operations by examining high-priority alerts (**High**).

## 2. Tools and Environment

| Category | Details |
|---|---|
| Tool | Hayabusa |
| Operating System | Windows |
| Terminal | PowerShell |
| Output Format | CSV (Timeline Report) |
| Analysis Type | Windows Event Log Analysis |
| Project Category | Blue Team / SOC Analysis |

## 3. Analysis Process

### 3.1. Initiating the Log Scan with Hayabusa

Hayabusa was executed through an elevated PowerShell terminal.

The `--live-analysis` and `--no-wizard` parameters were used to initiate live system log analysis.

As a result, Windows Event Logs were scanned, and detailed analysis results were exported in CSV format.

### 3.2. Reviewing the CSV Timeline Report

The CSV report generated by Hayabusa was opened in a spreadsheet application for further investigation.

The report contained the following fields:

- `Timestamp`
- `RuleTitle`
- `Level`
- `Computer`
- `Channel`
- `EventID`
- `RecordID`
- `Details`
- `ExtraField`
- `RuleID`

These fields were used to examine event timestamps, severity levels, associated computer and channel information, and event details.

### 3.3. Filtering High-Severity Alerts

As part of the analysis, alerts classified as **High** severity were filtered and investigated as a priority.

The detailed investigation of other alert levels (Critical, Medium, Low, and Informational) was outside the scope of this study.

Following the filtering process, most of the examined records were associated with **Event ID 1033**, while one record was associated with **Event ID 1034**.

### 3.4. Investigating Event IDs and Event Details

The `Details` column of the High-severity records was examined to identify the software associated with the events.

The investigation revealed installation and uninstallation records related to the following software:

- Microsoft .NET Host
- Microsoft .NET Host FX Resolver
- Microsoft .NET Runtime
- Microsoft Windows Desktop Runtime
- Oracle VirtualBox (7.2.20)
- Java 8 Update 51
- Java Auto Updater
- Microsoft Visual C++ 2008 Redistributable
- Wazuh Agent
- Microsoft SQL Server Database Engine Services
- Samsung-related components and other legitimate software

Details such as software versions, vendors, and operation statuses were evaluated during the investigation.

## 4. Findings and Analysis

Most of the investigated High-severity records were found to be associated with Windows Installer (MSI) operations.

The relevant Event IDs were evaluated as follows:

| Event ID | Description |
|---|---|
| 1033 | Windows Installer product installation information |
| 1034 | Windows Installer product removal events |

After examining the event details, the records were assessed as being related to installation and uninstallation activities involving legitimate software such as Microsoft .NET, Oracle VirtualBox, Java, and other applications.

Therefore, the investigated MSI records were evaluated as normal software management activities rather than indicators of malicious activity.

This investigation demonstrated that security alerts should not be interpreted solely based on their severity levels. Event details must also be examined to understand their context.

**Assessment:** The investigated MSI records were classified as false positives. This assessment applies only to the relevant High-severity records examined within the scope of this analysis. It does not establish that the entire system is free from malicious activity.

## 6. Conclusion

In this project, Windows Event Log analysis was performed using Hayabusa, and high-priority security detections were investigated through the generated CSV Timeline report.

Throughout the analysis, practical experience was gained in the following areas:

- Analyzing Windows Event Logs.
- Reviewing CSV-based Timeline reports.
- Filtering High-severity alerts.
- Investigating Event ID 1033 and 1034 records.
- Evaluating software installation and uninstallation activities.
- Analyzing false positive detections.

One of the most important takeaways from this project was understanding that a security alert generated by an analysis tool does not automatically indicate malicious activity. Examining event details and validating findings are essential for accurate security analysis.
